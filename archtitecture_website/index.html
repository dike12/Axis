Key Business Logic — Income Rollover Rule
⚡
The Rollover Rule — Most Critical Backend Logic
When a transaction is type credit (income) AND its date is >= income_cutoff_day (default: 20th), the backend automatically sets effective_date = 1st of the following month and marks is_shifted = TRUE. If shift_override = TRUE, this logic is skipped for that transaction. All dashboard metrics, budget actuals, and analysis use effective_date — never date. The frontend Ledger shows the real date with a "Shifted" badge when is_shifted = TRUE. Changing income_cutoff_day in settings triggers recalculation of ALL historical transactions.
